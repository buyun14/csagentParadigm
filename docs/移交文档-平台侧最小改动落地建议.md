# 移交文档：老低代码平台最小改动落地建议

> 目标读者：平台侧技术负责人/实施团队。
> 背景：老系统已具备 ASR/TTS/低延迟/NLP 兜底等能力，但 LLM agent 设计上**缺少"历史上下文/信息收集清单"类全局变量**，导致每轮 LLM 调用无法感知前文，只能靠堆提示词绕路——这是幻觉与记忆问题的根因（已与负责人确认）。
> 结论：**无需重做工作流**，在原有平台补几个全局变量 + 调整节点 prompt 模板即可；本项目的 `csagentParadigm` 是这条路径的可运行参考实现。

---

## 一、需要新增的全局变量（平台侧）

| 变量名 | 类型 | 说明 | 范式对应 |
|---|---|---|---|
| `${last_exchange}` | 字符串 | 上一轮"提问 + 客户回复" | `recent_history`（最近对话） |
| `${collected_info}` | JSON/文本 | 已收集信息清单：汽车品牌/汽车车系/所在城市/预计购车时间/客户姓氏/手机尾号 | `collected_slots` |
| `${current_node}` | 字符串 | 当前流程节点/状态 | `current_state` |
| `${dialog_summary}` | 字符串 | 早期对话摘要（可选，长对话时由平台或上游生成） | `summary.ts` rolling summary |
| `${previous_hit}` | 字符串 | 上一轮命中的回答分支（辅助护栏/连续性判断） | `lastDecision.intent` |

> 平台若不便做摘要，可先用 `last_exchange + collected_info + current_node` 三变量起步——这已能解决 90% 的"失忆"问题。

## 二、节点 prompt 模板改造示例

老系统模板（现状）：
```text
# 角色
你是一位专业的汽车销售平台客服……
## 回答分支
${branches}
## 示例对话
- 提问：${ask}
- 客户回复：[客户的回复]
- 系统回复：[从回答分支选择最合适的回复]
## 生成 JSON
{"hit": "命中分支","汽车品牌": "...","汽车车系": "..."}
```

改造后（在头部注入上下文变量，其余保留）：
```text
# 角色
你是一位专业的汽车销售平台客服……
## 对话上下文
- 当前节点：${current_node}
- 已收集信息：${collected_info}（未收集的字段留空，已收集的字段不要重复询问）
- 上一轮对话：${last_exchange}
- 历史摘要：${dialog_summary}（如无则为空）
## 回答分支
${branches}
## 示例对话
- 提问：${ask}
- 客户回复：[客户的回复]
- 系统回复：[从回答分支选择最合适的回复；未命中分支时输出 "UNMATCH"]
## 生成 JSON
{"hit": "命中分支","汽车品牌": "...","汽车车系": "...","汽车品牌": "..."}
```

**关键改动点**：
1. 注入三个上下文变量（红字部分）；
2. 增加规则"已收集的字段不要重复询问"（对应范式"已确认信息不回问"）；
3. 保留老系统强项：ASR 纠错技能、热词词典、`${branches}`、`UNMATCH`、优先级知识库全部不动。

## 三、范式参考实现映射（可直接对照移植）

| 能力 | 范式实现 | 移植到平台的方式 |
|---|---|---|
| 状态推进 | `state-machine.ts`（7 状态 + 各分支话术） | 每个流程节点 = 一个状态；跳转节点按状态迁移表配置 |
| 意图/实体 | `intent.ts` + `asr-corrections.ts` | 节点 prompt 内保留 ASR 纠错技能 + 热词词典（老系统已有） |
| 优先级知识库 | `legacy/matcher.ts` + `knowledge-entries.ts` | 老系统知识库机制不动，直接复用 |
| 多答案轮次 | `legacy/special-tokens.ts` | 老系统 answers 数组天然支持（语音播放顺序） |
| 无应答/无法回答 | `special-tokens.ts`（计数） | 平台已有 AI_UNKNOWN / USER_NOT_ANSWER 信号，补计数逻辑即可 |
| 护栏复核 | `engine.ts` evaluateGuardrail | 平台 NLP 层已做兜底，可在 LLM 输出后再过一遍护栏 |

## 四、验收指标建议

| 指标 | 验收方式 | 预期 |
|---|---|---|
| 上下文连续性 | 对话 5 轮后问"我刚才说的品牌是什么" | 能正确复述 |
| 不回问 | 已确认品牌后不再出现"您关注哪个品牌" | 全程 0 次重复追问 |
| 信息完整率 | 完整闭环对话，6 个采集字段 | 全部收集且值正确 |
| 护栏命中 | 输入辱骂/反感表达 | 触发退出话术并结束 |
| 首字延迟 | 快通道 first_token 指标 | 可观测、可比对 |
| 缓存命中 | 开场/结束/辱骂等固定话术 | 跳过 LLM 直接返回 |

## 五、双方分工建议

| 事项 | 责任方 |
|---|---|
| ASR/TTS/外呼/静音信号 | 平台侧（现有能力） |
| 新增全局变量 + 节点模板改造 | 平台侧（2-3 个变量，改动小） |
| 状态机/迁移表/prompt 模板/验收口径 | 可参考本项目交付物（`docs/` + `src/lib/agent/`） |
| 知识库数据 | 老系统数据已导入（`legacy/`），可直接作为平台侧配置回填 |
